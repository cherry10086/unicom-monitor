# 联通资费专区 · 加装包 5G 上网服务方案监控

监控中国联通资费专区（<https://img.client.10010.com/zifeizhuanquwt/index.html>）中
**河北-沧州 · 加装包** 下的资费方案，筛出「其他服务内容」里含
**5G上网服务 / 5G-A上网服务（下行峰值 xGbps / xxxMbps）** 的方案，
再二次筛出**智慧沃家共享版用户可订购**的方案。

每 12 小时自动跑一次，每次产出两组数据。

结果"完整性"是可判定的：只要有一个分类没抓到（接口报错、被网关拦截、分类改名），
本次就不会写正式结果、不做新增/下线对比，而是写 `partial_*` 并以退出码 2 结束——
宁可不给结论，也不把「没抓到」当成「已下线」。

> 本机实测：Node.js 与 Python 均未安装，因此脚本用 PowerShell 直接调接口实现，
> 不依赖任何需要额外安装的东西。

## 二、快速开始

### 1. 先自检（确认接口通、地区对）

先切到本目录，再用相对路径执行（下面所有命令都假定你已经在脚本所在目录）：

```bash
cd /d <本目录>
powershell -NoProfile -ExecutionPolicy Bypass -File .\monitor.ps1 -SelfTest
```

自检除了读目录，还会**抽查一个分类**：走一次三级选项接口与方案明细接口，
并校验「返回条数 = 请求的 ID 数」，所以 batchSize 配错、被网关拦成非 JSON 这类问题自检就能发现。

### 2. 手动跑一次

```bash
.\run-monitor.cmd
```

跑完后看 `output\latest\summary.txt`，这就是本次的两组结果。

### 3. 注册每 12 小时自动运行

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-task.ps1
```

默认注册计划任务 `UnicomPlanMonitor`，每天 **08:00 和 20:00** 各跑一次（一个任务、两个触发器）。
建议用**管理员**身份执行：这样才能以 S4U 方式注册——注销后也会运行，且不会弹出控制台窗口；
非管理员会自动退回「只使用交互方式」，脚本会明确提示「注销后不会运行」。

注册完想立刻验证一次（会等任务跑完再给结论）：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-task.ps1 -RunNow
```

查看任务状态：

```bash
powershell -NoProfile -Command "Get-ScheduledTask -TaskName UnicomPlanMonitor | Get-ScheduledTaskInfo"
```

卸载任务：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-task.ps1 -Remove
```

## 四、两组数据分别是什么

### 第一组 `groupA_all_matches.json`
所有**「其他服务内容」命中 5G 上网服务**的方案（`config.json` 里
`keywords.contentPattern` 的正则）。

### 第二组 `groupB_wojia_eligible.json`
第一组里，**智慧沃家共享版用户可订购**的方案。筛选规则见下一节。

### 汇总报告 `summary.txt`
除了上面两组编号，还逐条列出每个命中方案的「其他服务内容」「适用范围」
「智慧沃家判定」「订购限制」，方便人工核对。

### 什么情况下会写 `partial_*.json`
只要本次**结果不可信**，就只写 `partial_*`，**四个正式文件一个字都不动**，并以退出码 2 结束：

- 有分类抓取失败（接口报错、被网关拦、超时）；
- `config.json` 里的分类名在页面上已经不存在（上游改名 / 配置打错字）。

这样不会出现「没抓到的方案被当成已下线」「基线被残缺数据覆盖」这类误报。
`summary.txt` / `partial_summary.txt` 顶部会写清本次为什么不可信。

## 五、筛选规则（重点）

### 1. 第一组怎么判「命中 5G 上网服务」

接口返回的每个方案有个字段 `serviceContent`，页面上就是**「其他服务内容」**。
联通把 5G 上网服务按速率分档，实际文案有这几种写法（都来自真实数据）：

| 实际文案 | 含义 |
|---|---|
| `包含5G基础服务（下行峰值速率最高300Mbps）。` | 5G 基础档 |
| `包含5G优享服务（下行峰值速率最高500Mbps）。` | 5G 优享档 |
| `并享有5G上网服务（下行峰值1Gbps，该速率仅主卡使用，主副卡不可共享）` | 5G 上网服务 |
| `包含5G极速服务（下行峰值速率最高1Gbps）` | 5G 极速档 |
| `…可为用户提供5G优享服务。`（5G升级包系列） | 5G 优享档 |
| `…可为用户提供5G基础服务。`（5G加油包系列） | 5G 基础档 |
| `5G上网服务与5G网络服务质量VVIP` | 5G 上网服务 |

所以默认正则是：

```
5G[\u2010\u2011\u2012\u2013-]?A?(上网|基础|优享|极速)服务|5G[\u2010\u2011\u2012\u2013-]?A?尝鲜网速|下行峰值|下行速率最高
```

> 注意连字符必须写成可选的 `[\u2010\u2011\u2012\u2013-]?`，不能写成 `5G-A?`：
> 后者的 `-` 是必须出现的字面字符，而线上文案是「5G上网服务」（没有连字符），
> 会导致整条分支失效——只能靠 `下行峰值` / `下行速率最高` 兜底，漏掉只有服务名、
> 没有速率数字的方案（例如 `5G升级包`、`5G加油包`、`5G-A加速体验包`）。
> 方括号里的 `\u2010`～`\u2013` 是线上真实出现过的非 ASCII 连字符。

要收窄/放宽，改 `config.json` 的 `keywords.contentPattern` 即可。
还有一类写法是「提供相应的**5G优享速率网络服务**」「可为用户提供**5G基础速率服务**」（约 40 条），
它们不含「服务名」也不含「下行峰值」，默认不命中；想收的话把
`(上网|基础|优享|极速)服务` 改成 `(上网|基础|优享|极速)(速率)?(网络)?服务`，但命中范围会同时放宽。

### 2. 第二组怎么判「智慧沃家共享版可订购」

判据来自方案字段 `useScope`（页面上是**「适用范围」**）与「其他事项」。
**方案名称不参与判定**：名字里带「（智慧沃家共享版）」只是产品归属（说明这个产品就是给共享版用户的），
不是订购限制，把它算进来会把这类产品误判成"不能订购"。规则：

1. 文案里**出现「智慧沃家」且命中排除条款** → 判定 `excluded`，剔除。
   排除条款里的否定词必须直接作用在**订购 / 办理 / 受理 / 渠道**上，例如：
   - `智慧沃家共享版用户不可互联网渠道订购`
   - `智慧沃家共享版用户不支持线上订购`
   - `主卡、智慧沃家共享版成员用户不可办理`
   - `除2I、达量限速、智慧沃家共享版用户外，其余河北联通移网用户均可订购`
   - `智慧沃家5G极享“三千兆”融合套餐用户与联通PLUS会员互斥，不能订购`

   「只限该成员使用，其他成员不可**共享**」「仅限本人使用」「不可退订」这类是**使用与共享规则**，
   文案本身说明智慧沃家成员可以订购，所以**不算**排除条款。
2. 文案里出现「智慧沃家」且命中允许条款 → 判定 `allowed`，保留。例如：
   - `河北联通移网手机用户及智慧沃家共享版成员可订购。`
   - `适用于智慧沃家共享版用户`（共享版专区产品的常见写法）
3. 出现「智慧沃家」但两条都不匹配 → 判定 `unclear`，**保守按不可订购处理**（报告里会标注原因）。
4. 文案里**没提「智慧沃家」** → 判定 `unmentioned`，保留。

### 3. 两种筛选模式（`config.json` → `wojia.mode`）

| 模式 | 行为 | 适用场景 |
|---|---|---|
| `explicit`（默认） | 剔除 `excluded`（文案里明确写了智慧沃家不能订购）与 `unclear`（提到智慧沃家但两条规则都没命中） | 严格按「将智慧沃家共享版用户不能订购的方案去除」 |
| `strict` | 再额外剔除**适用范围限定为其他主套餐用户**的方案（如「仅限腾讯王卡套餐用户办理」「适用于订购5G畅越冰激凌升级版39元」） | 想只看真正能下单的 |

> **重要提醒**：截至 2026-09-09 的实测数据，第一组命中的 27 个方案里，
> **没有一个**在适用范围中排除智慧沃家共享版（判定都是 `unmentioned`），
> 所以默认 `explicit` 模式下第二组和第一组完全相同。但其中 **26 个都限定了别的主套餐**
> （王卡系列、畅越冰激凌升级版），普通智慧沃家共享版用户实际是订不了的。
> 报告里的「【参考】」小节列出的是**第二组中「没有」限定其他主套餐**的方案，
> 也就是最可能真正能下单的那几个（上面那批数据里是 0 个）；
> 被限定了别的主套餐的方案不会单独成节，只在【第一组】逐条清单里以
> 「订购限制：适用范围限定了其他主套餐」标注。如果你想要的就是「真正能下单的」，
> 把 `wojia.mode` 改成 `strict`。

## 六、配置说明（`config.json`）

| 配置项 | 说明 |
|---|---|
| `region.provinceId / cityId` | 地区编码。河北=018，沧州=180。换地区时同时改 `provinceName / cityName` |
| `scan.firstLevelNames` | 一级选项卡，默认 `["加装包"]` |
| `scan.secondLevelNames` | 二级选项卡，默认六个全扫。页面同一时间只能选一个，脚本会自动逐个扫；**如果某个名字在页面上已经不存在，本次会按"结果不完整"处理（只写 partial_*、退出码 2）并在日志里列出页面现用的名字** |
| `scan.tariffAttributes` | `2`=本省资费，`1`=全国资费。默认两个都扫 |
| `keywords.contentPattern` | 第一组的内容匹配正则（注意连字符写法，见上一节） |
| `wojia.mode` | `explicit` / `strict`，见上 |
| `wojia.negativePattern` / `positivePattern` | 智慧沃家的排除 / 允许条款正则（否定词必须作用在订购/办理/受理/渠道上） |
| `wojia.restrictionPattern` | 判断适用范围是否限定其他主套餐的正则（已排除「不限」「达量限速」「限量」这类字眼） |
| `http.retry` | 接口请求失败时的**总尝试次数**，默认 3（也就是最多重试 2 次）；传输层异常、返回非 JSON、`code != 0000` 都会重试 |
| `http.batchSize` | 每次接口请求携带的方案 ID 数，默认 80。**接口硬上限是 100**（实测 101 就返回 `code=0001 查询超过数量限制`），写大了会自动按 100 处理并打 WARN；写 0 或删掉该键会直接报错退出（而不是死循环） |
| `http.delayMs` | 请求间隔毫秒，默认 150 |

> 编辑 `config.json` **必须保持 UTF-8**（带不带 BOM 都行）。存成 ANSI/GBK 会让中文配置变成乱码，
> 所有中文正则随之失效——脚本会检测并直接报错退出，不会静默给出「第一组 0 个」。

### 只扫「权益包」和「其他」

把 `scan.secondLevelNames` 改成：

```json
"secondLevelNames": ["权益包", "其他"]
```

### 想连主套餐一起扫

把 `scan.firstLevelNames` 改成 `["加装包", "套餐"]`。
（腾讯王卡5G版 99/129/159/199/239/299/399 元套餐的「其他服务内容」里
也写着「包含5G优享服务（下行峰值速率最高500Mbps）」这类内容。）

## 七、常见问题

**Q：脚本是怎么拿到数据的？会不会因为页面改版失效？**
A：脚本直接调用资费专区的后端接口，不走浏览器：

| 用途 | 接口 |
|---|---|
| 读取目录（一级/二级选项卡） | `POST /servicequerybusiness/queryTariffNew/indexData` |
| 读取三级选项（页面上的「全选」那一层） | `POST /servicequerybusiness/queryTariffNew/threeLevelName` |
| 读取方案明细 | `POST /servicequerybusiness/queryTariffNew/operateData/{方案ID以下划线连接}` |

页面改版如果改了接口路径或参数，脚本会在日志里报
`接口返回异常：Path=... code=...`；**如果因此没能抓全，本次结果不会被当成正式结果**
（只写 `partial_*`、跳过新增/下线对比、以退出码 2 结束），不会把"没抓到"当成"已下线"。

**Q：退出码分别是什么意思？**

| 退出码 | 含义 |
|---|---|
| 0 | 正常完成（结果完整，正式文件已更新） |
| 1 | 运行失败（配置错误、全部分类抓取失败、写文件失败等，详见 `output\logs`） |
| 2 | 运行完成但**结果不完整**（有分类抓取失败，或配置里的分类名在页面上不存在）→ 只写了 `partial_*` |
| 3 | 已有一次运行正在进行，本次跳过（互斥锁被占用） |

`run-monitor.cmd` 在非 0 时会打印 `[ERROR] monitor.ps1 exited with code N`。

**Q：为什么计划任务到点没运行？**
A：默认注册的任务是「只使用交互方式」时，**注销 / 未登录不会运行**。用**管理员**身份重新执行
`setup-task.ps1` 会改用 S4U 注册（注销后也能跑、无控制台窗口）；
用 `setup-task.ps1 -RunNow` 可以立刻验证一次，它会等任务跑完再告诉你结果
（看到 `LastTaskResult = 267009` 表示任务还在运行，不是失败）。

**Q：为什么输出里有的字段是 `unmentioned`？**
A：表示该方案的适用范围文案里没提「智慧沃家」，即**没有明确排除**它。
这不等于一定能办——还要看适用范围有没有限定别的主套餐。

**Q：报告里中文乱码？**
A：`output\latest\summary.txt` 和 JSON 都是 UTF-8。用 VS Code / 记事本
（Win10 1903 以上）打开即可。`config.json` 也必须存成 UTF-8（脚本会检查）。
PowerShell 控制台里如果乱码，先执行 `chcp 65001`
（`run-monitor.cmd` 会自己切到 65001，并在结束时还原原来的代码页）。

**Q：跑一次多久？**
A：实测约 20 秒（扫 6 个二级分类 × 本省+全国，共 2149 条方案；数据量会随时间变化）。

**Q：历史归档会不会越积越多？**
A：每次完整运行会在 `output\history\` 下建一个时间戳目录（内含 groupA / groupB / summary 三个文件），
每个目录约 50 KB。按每 12 小时一次算，一年约 1.8 MB，可以忽略。
想关掉就用 `-NoArchive` 参数运行（不会再创建 history 目录）。
结果不完整的运行不会写归档。
